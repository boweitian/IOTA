# IOTA 进展反思：以 Map · Walker · Soul 重新审计

日期：2026-10-11。依据：本目录源码、现有 JSON、Slurm 日志、`../verify/` 实验及当前 `../papers/monad.tex`。本次没有运行新的模型测量，没有重建系统；进行了源码核查、现有产物核查和不加载模型的 CPU 反例检查。文中的产品设计与实验方案是待验证方案。

## 1. 对当前进展的判断

当前完成的是一套有限词对的表征探测原型，以及探测结果的展示。**尚未完成能够持续积累证据的概念地图、主动发现系统或经过验证的 Model Semantic Identity。** README 中的 “MVP framework complete” 不能代表用户所要求的 MVP 已完成。

此前最根本的错误，是把 Map、Walker、Soul 当作三个需要填满的模块，然后把差分向量、词表遍历和指标摘要分别装进去。真正的工程关系应当是：地图保存可检验的结构假设；Walker 根据地图的缺口和矛盾选择实验、提出新假设并更新结构；Soul 从经过独立检验的结构和探索记录中提取。模块名称与产品文案不能代替这条证据链。

同时也不能把此前研究全部判为无价值。`verify/` 包含实际模型实验和重要的负结果，它们能约束下一步设计。问题在于后来没有让这些证据约束 IOTA 的实现与结论。

## 2. 现有实现与目标的具体距离

| 对象 | 当前实现与证据 | 仍然缺失的能力 |
|---|---|---|
| Map | 预设形容词对在 40 个槽位模板中的差分；平均方向与 LOO cosine | 有条件的概念关系、边界、局部结构及其连接；持久证据、反证和版本记录；未见情境预测 |
| Walker | 从词库中选择尚未写入 Map 的词对；多数策略取列表首项 | 根据不确定性选择实验；反事实生成；已有关系的复验与撤销；发现新结构；真实预算约束 |
| Soul | 按 LOO 阈值筛选词对，再添加摘要 | 在明确分布内验证的结构身份；模型特异性；不确定性校准；跨版本变化及证据 |
| 比较 | LOO 强弱比较，另有直接跨模型向量点积 | 可比较的测量协议、内部坐标对齐或坐标无关的结构比较；独立身份检验 |
| Human–Agent Alignment | ethics 词表 | 用户授权与任务约束的显式定义；语义边界与实际行动决策的关联 |

### Map：真实测量也被赋予了超出证据的含义

- `iota/atlas.py:187–194` 实际读取最终 hidden state 的最后一个 token；`_extract_direction_multi_context()` 的 `layer` 参数未用于抽取。`_find_peak_layer()` 在第 344–349 行直接返回 `num_layers // 2`。因此保存的层标签不能解释为测量得到的峰值层。
- `layer_depth_profile` 为每层创建空列表，未填入测量；现有 3B Map 有 37 个空 profile。
- Map 的主要对象是单个词对的平均向量，不包含语境条件下的关系估计。`cos_with_main` 只有对主词对的平均方向相似度，尚无关系稳定性检验。图中的连线表示预设词对，不是实验发现的网络关系。
- `_find_invariant_markers()` 直接取排名前十，没有合格门槛；即使全部很弱，也会输出 invariant markers。
- 仅留下均值、标准差、范数和模板不足以支持后续完整复验；缺少逐次观测、模型 revision、测量协议版本、失败记录、随机种子及采样配置等证据索引。

平均方向存在，最多说明该操作在所测模板中有共享分量。它不自动说明已经找到概念的完整几何，更不说明该共享分量是模型独特的语义身份。多个普通词对都能达到相似一致性，正是需要进一步区分语义与测量伪影的理由。

### Walker：还没有实际的发现闭环

- `build_map()` 先处理整个词库；`walker.py:211–220` 又排除所有已在地图中的词对。不加载模型的 CPU 检查确认：完整词库初始 Map 下 `_select_next_target()` 返回 `None`。默认完整建图成功后，探索没有目标。
- `INFORMATION_GAIN` 与 `ANOMALY` 实际都返回 `remaining_pairs[0]`，没有信息增益计算或异常驱动选题。
- `_explore_concept()` 复用固定模板，没有生成新的反事实实验。`concepts_discovered` 统计的是已知词对被执行过，不能解释为发现了未知概念。
- 声明了 `exploration_budget`，但没有跟踪或扣减实际调用。停止条件主要基于 LOO 大小，不能表示新证据的边际收益。
- `_update_map()` 丢弃语境和部分已有指标，写入 `contexts=[]`、`layer=0`；没有重算 Map markers 或保存完整轨迹。
- `scripts/mvp.py:70–99` 先生成 Soulprint，再选择性运行 Walker，最后仍展示此前的 Soulprint。即使未来 Walker 更新成功，当前交付流程也没有重新提取身份。

修复“初始 Map 太满”只能让循环跑起来。循环的动作若仍然只是执行剩余词对，就仍然没有实现主动发现。

### Soul：占位参数进入了模型报告

- `soulprint.py:184–189` 用任意的 `LOO > 0.4` 判断 invariant；所谓 confidence 是 `min(n/40, 1) * max(0, 1-std)`，没有校准，不能视为结论成立的概率。
- 第 223–228 行为每个词对写入单位矩阵、`peak_layer=15`、`plateau_depth=8`、`decay_rate=0.3`。这些不是深度测量。
- 第 242–246 行写入 `honesty_tendency=0.5`、`caution_level=0.5`、`generation_style=neutral`。说明文字承认缺少行为实验，但数值仍作为模型字段导出。
- 第 268–270 行无条件宣称中间层稳定。已有验证报告并未支持接近 1 的深度平台，不能用这句摘要覆盖负结果。
- “某词对在另一模型的 markers 中没有出现”也不能解释为另一模型没有这个概念；可能是阈值、覆盖、失败或不确定性造成的缺失。

这些字段应当标记为未测量；未经确认的候选结构必须保留候选状态。缺少证据不能靠默认数值补齐。

### 现有输出必须区分来源

1. **7B demo：** `scripts/demo.py:100–103` 使用 `np.random.randn(3584)` 生成方向。其 LOO 数据复用了真实验证结果，但几何向量为随机占位；保存的 `Qwen2_5-7B_map.json` 不能作为实测几何地图。它还把全层最大 LOO 放进 `loo_cosine_mean`，与原报告使用的预先限定深度带不同。
2. **3B 推理：** `slurm-2055885.log` 记录了真实推理，得到 13 个词对；`Qwen_Qwen2.5-3B_map.json` 包含相应指标。这个工作是可保留的表征探测结果，但保存层号与 Soul 深度、行为字段仍受上述问题影响。
3. **指标展示：** `scripts/demo_results.py` 明确说明方向向量不可用、未运行新推理、全层峰值不是独立测试结果。这个来源说明应保留，但该报告本身也没有实现概念地图或自主发现。

本次读取 JSON 确认：7B 保存 21 个词对、方向维度 3584、层标签全为 15；3B 保存 13 个词对、方向维度 2048、层标签全为 18。两份 Soulprint 的深度参数均为同一组 `(15, 8, 0.3)`，行为参数均为上述默认值。

### 跨模型比较没有成立

`atlas.py:393–397` 直接对两个模型的方向做点积。CPU 调用现有两份 Map 得到 `ValueError: shapes (3584,) and (2048,) not aligned`。

维度相同也不够：检查将同一个合成方向从 `(1,0)` 换到旋转后的等价坐标 `(0,1)`，当前比较函数将其称为 “Significant conceptual divergence”。因此比较前必须说明共同坐标、对齐方法或所用结构量。模型各自的 LOO 数值可作协议限定的描述统计，但它不能单独回答授权与隐私的关系发生了什么变化。

## 3. Monad Theory 应当成为可检验的约束，而不是替结论担保

旧 `MATH_AUDIT.md` 审计对象是旧 PDF；当前 `papers/monad.tex` 的定义与章节已经变化。本次没有对新版做全面数学审稿，也不把旧审计中的所有编号结论直接套给新版。以下是本次对当前文本的独立核查。

### 当前 Redistribution 的必要条件过强

第 451 行要求每个有非零权重的隐藏项分别为仿射。但式中的梯度只取决于它们的加权和。取隐藏函数 `φ₁(u)=u²`、`φ₂(u)=u²+u`，相应系数为 `1`、`−1`；加权和为 `−u`，梯度恒定，尽管两项都非仿射。

因此按该式的恒定梯度口径，需要约束的是加权和，而不能未经排除抵消就给出逐项必要条件。非正交、过完备字典中的数量坐标、投影与物理空间梯度之间的关系也需明确。

### 当前 Orbit merging 条件不足

第 588–608 行试图从共享参数、同类残差同号、核梯度正内积和累计残差发散推出共同方向。正内积并不保证方向相同，以下模型满足所列条件却保持方向差异：

令 `Fθ(h)=θ f(h)`，其中 `f(h)=h₁+h₂²/2`；取两个训练状态 `(1,0)`、`(1,1)`，标签都为 `+1`，使用交叉熵。则：

- 两点的 `f` 值为 `1`、`1.5`，共享切核为 `K(h,hᵢ)=f(h)f(hᵢ)`。
- 两点的 `∇f` 为 `(1,0)`、`(1,1)`；核梯度在任一样本下的内积都为正，同类残差始终为负。
- 正学习率下 `θ` 持续增大且发散；由参数增量与残差总量的上下界，累计残差也发散。
- 表达方向始终为 `θ(1,0)`、`θ(1,1)`，夹角固定为 45°，不趋于同一个方向。

CPU 核算得到最小核梯度内积 `1.0`；相对于平均方向的平均 cosine 对所有正 `θ` 均为约 `0.921555`，不是趋于 1。需要补充真正的方向收缩或共同主导分量假设，不能从正相关直接推出 merging。

此外，当前 orbit 用“等于均值向量”定义成员，却用 cosine 的均值为 1 推断属于该集合；正比例而范数不同的向量也能让 cosine 为 1。这要求先明确 identity 指单位方向、完整梯度还是其他结构。

本次还发现当前 Tex 中 36 个唯一的 `ref/eqref/pageref` 目标没有匹配的 label。这是源码引用核查，未执行 LaTeX 编译。

这些问题不意味着必须先完成整篇理论才能做产品。它们意味着 IOTA 应把理论命题登记为带适用条件的假设，用独立测量决定保留、限制或拒绝。不能用理论名称替代识别条件。

## 4. 正确的工程对象

### Map 的基础单位应是有证据的结构假设

一条地图记录至少应能回答：概念或候选因素是什么；关系是什么；在哪些状态与变换下预计成立；有什么观测、什么反例；使用了什么协议；不确定性是什么；下一次实验能怎样推翻它。

例如“可用的个人信息”与“获准用于当前任务的信息”的区别，是一个可以提出的结构假设。可以预测：保持数据内容不变、只撤销授权时，执行或披露边界会变化。这里描述的是待测假设，不是任何现有模型的发现。

几何层应保留局部方向或子空间及其适用范围，研究不同局部结构是否能连接。不能先把全部上下文平均成一个箭头，再把剩余差异都称为噪声。全局性需要明确测试域、变换集合与失败边界；有限测量不能证明所有上下文上的不变性。

### Walker 的动作应是选择并执行能区分假设的实验

最小循环应是：观察当前证据 → 提出或选择相互竞争的解释 → 挑选能区分解释的情境变换 → 保存响应及内部观测 → 更新结构与不确定性 → 决定复验、拆分、扩展或撤销。

候选生成可以用人工种子和 Monad Theory 的先验，但不应限定在永久不变的词表。探索器能够发现“原先的节点需要拆分”“关系只在某个边界内成立”“存在解释残差的候选因素”，才逐步接近发现未知基本结构。发现、命名和机制识别是不同步骤；生成一个新名称不算发现。

所谓“未知单子”需要先给出操作性识别标准：候选因素在独立数据中能解释或预测什么、是否只是已有因素的重命名、是否受词汇和长度等混淆影响、内部干预是否支持对应机制。未达到这些标准时应称为候选结构。

### Soul 应从通过检验的地图版本中提取

Soulprint 可以包含稳定关系、稳定边界、条件性结构、模型间差异和版本漂移。每项必须链接到具体地图版本、测试域和原始证据。稳定结构可能被多个模型共享，因此还要验证哪些组合真正具有身份区分能力。

内部表征证据、输出行为证据、内部干预证据应明确区分：黑盒响应只能建立行为语义图；读取 activation 不等于因果证明；干预的效果也需要语义与非语义对照。Soul 不应由单个一致性排序或默认人格分数构成。

Human–Agent Alignment 的连接点是：某种授权、隐私或不确定性结构怎样影响用户任务中的具体决定，以及这种影响是否符合明确的人类约束。模型稳定不等于符合用户意图；“obedient”词的表征不等于正确识别谁有权授权什么。

## 5. 重做顺序与验收

第一步应把产物恢复到其真实证据等级：随机 demo 几何标为示意；未知指标留空；撤回未测的深度与行为结论；把词对一致性称为表征探测统计。保留已有原始实验和负结果。

第二步选择一个有限但存在关系与冲突的区域，例如授权与隐私。以两个固定 revision 的开放权重模型、共同任务协议和明确操作性行为读出构造一张初始的证据地图。先让系统完整记录一次“提出假设—选择反事实—获得反例—修改关系—独立复验”的过程。

第三步单独评价 Walker。固定调用或 token 预算，比较主动选题、随机选题、固定测试清单；在多个随机种子下比较独立确认的有效关系、边界覆盖、预测误差和发现成本。初期可以在固定候选实验池上验证选题效率，但应明确这仍不等于开放式概念发现。候选生成能力需要另外对照，并验证新增候选的独立收益。

第四步才把满足下述条件的结构汇成 Soulprint，并评价版本比较能力。

| 验收问题 | 应如何检验 | 当前状态 |
|---|---|---|
| Map 是否解释并预测新情境？ | 按场景族、任务或变换留出独立确认集；冻结建图规则后评价预测和校准，避免同模板改写泄漏 | 未实现 |
| Walker 是否提高效率？ | 相同总预算、相同初始条件、多种子；确认集对探索器保持不可见；探索日志可重放 | 未实现 |
| Soul 是否反映身份与语义变化？ | 区分同一版本的重复采样与真实版本差异；报告漂移定位和误报；与常规行为指纹及 benchmark 比较 | 未实现 |

其中版本实验还必须固定 system prompt、解码配置和评测协议，以免把部署配置变化误判成权重变化。受控扰动可以先检验管线，但不能替代真实版本的结果。

下一份有意义的交付应当让读者可以追溯一条关系：它最初为什么被提出，Walker 为什么选择某个测试，模型实际给了什么响应，出现什么反例，地图怎样被修正，以及修正后的结构能否预测未见任务。只有建立这条链，Map 才开始成为资产，Walker 才开始成为引擎，Soul 才开始成为可交付的模型身份。
